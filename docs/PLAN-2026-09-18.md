# Kit v2 — the plan

One page. Evidence lives in `docs/RESEARCH-2026-09-18.md`; nothing loads that at runtime.

Labels: **[M]** measured from our own transcripts · **[C]** fetched and re-verified ·
**[S]** single source, unconfirmed · **[R]** refuted during review, do not do.

---

## The problem, in three numbers

- **[M]** Wall-clock = turns × ~5–12 s. Context size does not drive it: medians were 1.8 s
  under 200k, **6.4 s at 200–400k**, 5.8 s at 400–600k, 4.7 s at 600–900k — non-monotonic, so
  the 200k bucket's speed is not a context effect (it also carried much larger outputs).
  Fable and Opus cost the same per turn (5.7 s vs 5.2 s).
- **[M]** Of 1,493 model turns in one 310-minute session, **797 (53%) were the orchestrator's**.
- **[C]** The only published A/B of Claude Code fan-out: on **Fable 5** 2m15s alone, 7m00s
  with two subagents, 17m00s with five; on **Opus** 4m15s / 8m00s / 4m45s — so two subagents
  was the worst case on both, and five never beat sequential. "They were not faster on any
  task we timed."

**Conclusion: the loss is spawning for serial work, not agent count, not tokens.**
**[M]** Caching already runs at ~99% inside an agent (22.6M cache-read vs 364 fresh tokens).

## The four defects we found in this kit

1. **[M] The gate rule killed the reviews.** Four of five refuters died running
   `npm run check-all` — which in that repo is `tsc + eslint + ruff + mypy + pytest`, the full
   suite, while a `--fast` flag sat unused. Two ran it in parallel. The user killed them.
2. **[M] `maxTurns` does not bind.** Refuter declared 40, made 45 tool calls. Verifier
   declared 8, made 22.
3. **[M] Briefs do not carry enough.** Builders spend **36–50% of their turns before the first
   edit** (182-turn builder: first Edit at turn 66).
4. **[M] Nothing was ever measured.** Accept rate, turns per agent, gate runs per change —
   none of it recorded, so "is 40 minutes worth it" was unanswerable.

## What the kit got right and keeps

**[C]** One independent reviewer in a fresh context is the one part with evidence behind it:
CriticGPT's critiques beat paid human reviewers (63% natural bugs, >80% inserted); self-repair
gains are "modest… sometimes not present at all" because a model critiquing *its own* code is
the bottleneck; LLM judges demonstrably prefer their own output. **The same sources cap the
claim**: CriticGPT's own paper reports model nitpick and hallucination rates far above humans'
on a benchmark with no multi-file support, and a 2026 third-party PR benchmark puts Claude at
43.3% recall / 42.3% precision — one pass catches under half. **[M]** Our own surviving refuter
opened the client's XLSX with `zipfile`, compared `C2..AD2` against the code's header constant,
ran the constructor against 9 inputs and traced 9 call sites. Keep it, and expect padding.

Also kept: builder never grades itself · refuter never reads the builder's report · brief is an
immutable file · batching small changes · no phases, no personas, no spec-document tree.

## The changes, in payoff order

### 1. Raise the no-agent threshold. This is where the 25 minutes are.

Builder + refuter become the **exception**: security surface, or **>400 changed lines / >8
files**. Below that the main session makes the change itself at lower effort and notes it for
the batched review. The old threshold (2 files / 40 lines) was ~10× stricter than the
**[C]** 200–400 LOC window where review finds 70–90% of defects.

### 2. The gate runs once, in a shell, never inside a review agent

Diff-scoped and **under 60 seconds** — no test suite. Builder runs it as its last step; the
orchestrator pastes the verbatim output into the brief. **The refuter never runs it.**
**[S]** One instrumented run spent 11m46s on an agent wrapping a 0.2-second linter.

### 3. Split recall from precision across the two stages we already have

- **refuter = finder.** Recall-biased, passes through every candidate with a nameable failure
  scenario, drops nothing, and may return "no findings".
- **verifier = precision.** Three states **CONFIRMED / PLAUSIBLE / REFUTED, PLAUSIBLE by
  default** — **[S]**, read out of the shipped `code-review` skill by one research lane and not
  independently re-verified. REFUTED needs the line, constant or guard that makes the finding
  impossible. The exclusions and the >80% confidence floor live here.

**[C]** The two-stage shape itself is Anthropic's own `/security-review` architecture (finder →
per-candidate false-positive pass → drop below 8/10). It is the only change in the sweep with
any measured evidence attached, and that evidence is about **precision**, not catch-rate: LLM
agents cut SAST false-positive rates from >92% to as low as 6.3%, and reached 93.3% FP
identification on real CodeQL alerts. Putting "maximise recall" and "minimise false positives"
in one agent was the error.

**[C] One deliberate deviation:** that prompt's PRECEDENT 8 says client-side authz/authn gaps
are not vulnerabilities. Our `CLAUDE.md` names "any client-decidable rule" as a top surface.
**We invert it** and say so in the skill.

### 4. Briefs carry pre-resolved anchors and a tool-call budget

Target: **first edit by turn ~10, not turn 66.** CONTEXT carries resolved `path:LINE`, the exact
gate command, the exact test files, the base sha, and an explicit tool-call budget. Plus: no
agent may read or "analyse" a document wholesale — **[C]** BMAD's own bug report blames exactly
that for 80–100k-token steps.

### 5. Model routing: change the seat, keep the mechanism

Main session **Opus 5 (high)**; nothing pinned to Fable, so **Fable expiry stops being a failure
mode**. **[C]** Fable 5.1 is $10/$50 against Opus 5's $5/$25, and Anthropic's guidance is
"start with Opus 5… use Fable when your evals on Opus 5 at higher effort still fall short".
**[M]** The fallback already happened silently: 616 Opus turns against 179 Fable turns in one session.

Fable's remaining correct use: run the main session on Fable when the task is a hard design
decision you make yourself — **and spawn almost nothing.**

`scout` is deleted. **[C]** The built-in `Explore` agent does exactly that job and a
same-named user agent overrides it while keeping its own `model`; ours runs `haiku` with the
qartez tool list. Note **[C]** Haiku 4.5 ignores `effort` entirely.

### 6. Resume, do not re-spawn

**[C] documented, not yet exercised here.** A subagent stopped at `maxTurns` returns output
**marked partial** and can be resumed via `SendMessage` with full history and a warm cache.
The docs place `SendMessage` in the fixed set every background subagent keeps, independent of
agent teams — so pinning teams off does not disable it. We have not run a resume yet, so treat
the wall-clock saving as unmeasured.

### 7. The cheap confirmed settings

| change | why |
|---|---|
| `subagentPromptCacheTtl: "1h"` | **[C]** subagents get a 5-minute TTL by default even on a subscription. **[R]** as "the biggest lever" — 1h writes cost 2× and break even at ~1 turn in 20 pausing 5–60 min. Conditional win. |
| `omitClaudeMd: true` on verifier + locate, **paired with the tool rules in `initialPrompt`** | **[C]** worth ~4k tokens/spawn — but only **5–10%** of the 38–69k prefix, not the headline two lanes claimed. Unpaired it strips the qartez-not-Grep rule and costs more than it saves. |
| **keep** `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` | **[C]** live docs say the default really is three layers. Load-bearing. |
| `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS: "0"` | **[C]** teams cost ~7× tokens, and while enabled any *named* subagent becomes a full teammate session. |
| `worktree.baseRef: "head"` | **[C]** a worktree otherwise branches from the default branch with no deps and no `.env`. |
| read-only agents stay **out** of worktrees | **[C]** a different working directory forfeits the whole cached prefix. |
| stagger parallel siblings ~5 s, identical profiles | **[C]** a cache entry does not exist until the first response begins. **[M]** our two refuters launched 29 s apart; the second paid full price. |
| `disallowedTools: Edit, Write, NotebookEdit` on read-only agents | the `git status` before/after guard cannot attribute writes with background agents in flight, and cannot see write-then-revert. |

## Deliberately not doing

- **[R] No `advisorModel: fable`.** **[C]** "The advisor model's own read of the conversation is
  not cached — each advisor call processes the full transcript anew", and on subscription plans a
  Fable advisor **bills to usage credits, outside the plan**. At 2–3 consults on a 40–70k context
  that is 100–200k uncached Fable-rate tokens per agent. Experiment on one agent, never a default.
- **[R] No brief-review agent.** Its only evidence was one anonymous comment's unpublished
  evals, and it adds the one thing we are removing: a serial step.
- **[R] No `Stop` hook blocking session exit.** It turns every abandoned experiment into a
  forced review; **[C]** Anthropic's own security Action defaults `run-every-commit` to false,
  for false-positive reasons.
- **[R] No `async` gate hook.** Async hooks cannot gate, and the matcher fires once per edit.
- **[R] No forked reviewer** for correctness or security — a fork inherits the main session's
  model and destroys the independence the review exists for.
- **[R] No per-agent MCP tool allowlists** as a token play — **[C]** tool definitions are
  already deferred; only server *instructions prose* is not. Scope with `mcpServers:` instead.
- **No agent teams** — **[C]** ~7× the tokens of a standard session **when teammates run in
  plan mode**, which is the figure Anthropic publishes; off by default, and a named subagent
  silently becomes a teammate while they are on.
- **No BMAD / spec-kit / claude-flow / SuperClaude layer.** **[C]** Same feature, four flows:
  BMAD Full 2 days planning + 4 days implementation at $50 + $150, against Spec-Kit's 4h + 1d
  at $30 + $45, OpenSpec's 3h + 1d at $25 + $70 and BMAD Quick's 5h + 1.5d at $30 + $55 — the
  three light flows were "noise" apart from each other, and the heavy one cost ~2.7× the
  wall-clock.
- **No global behavioural skills** — **[C]** the skill listing is budgeted at 1% of the context
  window and drops least-invoked descriptions first, degrading qartez/ponytail/qmd triggering.

- **The Karpathy repo — not installed.** **[C]** One skill, 2,518 bytes; not by Karpathy
  (`multica-ai` / `forrestchang`); 28 commits, last push 2026-04-20, issues disabled, 101 open
  PRs, `license: null`. Its source post says these failures persisted *despite* CLAUDE.md
  instructions. Two rules actively fight this loop: "if unclear, stop and ask" cannot execute in
  a subagent with no user, and "every changed line traces to the request" argues a builder out
  of root-cause fixes.
- **`fable5.md` — five rules harvested, the rest becomes an output style.** Output styles are
  **[C]** not inherited by non-fork subagents and preserve the prompt cache, so the main-session
  protocol reaches the only seat that can use it at zero per-spawn cost. Harvested: **Baseline**,
  **INTENT**, **TWINS**, **SOURCE**, **anti-thrash**.

## Measuring it

**[C]** Use the free surfaces first: `/insights` (200 recent sessions →
`~/.claude/usage-data/report.html`), `/usage` (API vs wall duration, attribution by
subagent/skill/MCP server — note it resets on `/clear` and its cache line covers the main
conversation only), `/context`, and the per-agent transcripts at
`~/.claude/projects/{project}/{sessionId}/subagents/agent-*.jsonl`.

| metric | baseline **[M]** | target |
|---|---|---|
| turns per agent | builders 36–182 | < 25 |
| turns before first edit | 27–66 (36–50%) | < 10 |
| gate runs per change | 3+ | 1 |
| agents with no recorded result | 4 of 13 | 0 |
| must-fixes agreed / raised | never computed | > 70% (**[C]** industry 73.8% / 75.0%) |
| wall-clock per change | 25 min — **one builder's own run**, not a whole pipeline; the full builder+refuter+verifier chain for that change was ~50 min | < 10 min per agent |

Below ~70% accept rate means the **brief** is the defect, not the model.

**Experiments, in order.** (1) Threshold: redo a sub-400-line change inline at lower effort and
compare. (2) Effort sweep: refuter at `high` against diffs where `xhigh` found must-fixes.
(3) `/code-review high` against a hand-written refuter brief on the same diff — this could
retire an agent file. (4) Kit path against bare plan mode. **[C]** Nobody in the entire sweep
published a controlled quality measurement, so items 3 and the effort drop stay unproven until
we run them.
