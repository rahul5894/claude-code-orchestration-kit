## 2. Fan-out versus sequential

**[C]** Proxy-instrumented, hash-chained request captures, 2026-07-22 —
<https://systima.ai/blog/subagent-tax>

| model | sequential | two subagents | five subagents |
|---|---|---|---|
| Opus | 4 req / 295k tok / **4m15s** | 12 / 762k / **8m00s** | 15 / 945k / **4m45s** |
| Fable 5 | **2m15s** | **7m00s** | **17m00s** |

Haiku-pinned subagents under an Opus parent: 481k tokens / 3 requests / 3m45s against
762k / 8 requests / 8m00s for inherited Opus. Fable's subagents "took more turns over the same
work". Every unexpected full-prefix re-write happened with a same-profile sibling in flight.
Author caveats: one gateway, one task per lane, lanes back-to-back.

**[C]** Anthropic, cost/intelligence guide: the orchestrator pattern saved money in only two
measured situations — capping the cost tail on routine work, and work larger than one context
window — and *"on work a single model could handle alone, the same model at lower effort was
cheaper every time."* Prompt caching cut agent-loop cost **2.7–5.3×**.
<https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence>

**[C]** Anthropic, multi-agent research system: agents ~**4×** chat tokens, multi-agent ~**15×**;
token usage alone explains 80% of performance variance on BrowseComp; multi-agent wins only on
heavy parallelization, context-exceeding information, and many complex tools; *"most coding tasks
involve fewer truly parallelizable tasks than research."* The 90.2% figure is a search benchmark.
<https://www.anthropic.com/engineering/multi-agent-research-system>
Also: explicit effort-scaling rules in orchestrator prompts because "agents struggle to judge
appropriate effort"; vague subtask descriptions made subagents duplicate work; rewriting one
tool description gave a **40% decrease in task completion time**.

**[C]** Cognition, *Don't Build Multi-Agents*: "share full agent traces, not just individual
messages"; "actions carry implicit decisions, and conflicting decisions carry bad results";
multiple collaborating agents "only results in fragile systems".
<https://cognition.ai/blog/dont-build-multi-agents>

**[S]** Instrumented 23-agent workflow: 1,030 turns, ~44 turns/agent, ~70,614 tokens of context
per turn, 72.7M cache-read against 5.59M cache-creation; one phase wrapped a 0.2-second Python
linter in an agent that made 45 tool calls and took **11m46s** of a 41-minute round.
<https://github.com/anthropics/claude-code/issues/83873>

## 3. Review quality

- **[C]** CriticGPT: LLM critiques preferred over paid human contractor critiques in **63%** of
  natural-bug cases, **>80%** on inserted bugs; win rate on detected bugs 62.8% (60.5–65.1 CI).
  Counterweight from the same paper: nitpick and hallucination rates far above humans',
  comprehensiveness trades directly against hallucination, and the benchmark had **no multi-file
  support and no repository navigation**. <https://arxiv.org/html/2407.00215v1>
- **[C]** Self-repair (ICLR 2024): gains "modest, vary a lot between subsets, and are sometimes
  not present at all"; the bottleneck is the model critiquing its own code; a stronger critic
  produced substantially larger gains. <https://arxiv.org/abs/2306.09896>
- **[C]** Self-preference: an LLM scores its own output higher than equal-rated output from
  others, with a causal link to self-recognition. <https://arxiv.org/abs/2404.13076>
- **[C]** Qodo PR-Agent, 4,335 PRs / 22 repos / 238 developers: **73.8%** of bot comments
  accepted and implemented; average PR closure **5h52m → 8h20m (+42%)**.
  <https://arxiv.org/html/2412.18531v2>
- **[C]** ByteDance BitsAI-CR: **75.0%** precision in production after a dedicated
  ReviewFilter stage, 26.7% outdated rate for Go, 12k weekly active users.
  <https://arxiv.org/html/2501.15134v1>
- **[C]** 2026 third-party PR-reviewer benchmark, 67 PRs with a golden bug set: Claude **43.3%
  recall / 42.3% precision**; CodeRabbit 49.2%/24.8%; Graphite 7.5%/66.7%. Published by a vendor
  that ranked itself first — treat the ordering with suspicion, the magnitude as calibration.
- **[C]** MAST, 1,600+ annotated multi-agent traces, κ=0.88: step repetition **15.7%**,
  incorrect verification **9.10%**, no/incomplete verification **8.20%**, premature termination
  6.20%; failures concentrate in system design and coordination, not model capability.
  <https://arxiv.org/abs/2503.13657>
- **[C]** Agentless — fixed three-phase pipeline, no autonomous planning — highest among
  open-source approaches on SWE-bench Lite, 32.00%, **$0.70 per issue**.
  <https://arxiv.org/abs/2407.01489>
- **[C]** Cisco/SmartBear peer review: review **no more than 200–400 LOC**; 200–400 LOC over
  60–90 min yields **70–90% defect discovery**; ability diminishes beyond 400 LOC; density drops
  above 500 LOC/hour. Lightweight tool-assisted review takes **<20% the time of formal review and
  finds just as many bugs**; spot-checking **20–33%** gave lower defect density for minimal time.
  On checklists: *"Omissions in particular are the hardest defects to find because it's difficult
  to review something that isn't there."*
- **[C]** Anthropic's `/security-review` prompt: a **>80% confidence floor**, three blanket
  exclusions, **17 numbered HARD EXCLUSIONS** (the list numbers two entries "16"), **12
  PRECEDENTS**, and a **3-step pipeline** — one finder sub-task, one parallel false-positive
  sub-task per candidate, then drop everything scored below 8/10. Its **PRECEDENT 8** excludes
  client-side authz/authn gaps as non-vulnerabilities — which contradicts this kit's
  "any client-decidable rule" surface, so we invert it.
  <https://raw.githubusercontent.com/anthropics/claude-code-security-review/main/.claude/commands/security-review.md>
- **[C]** The GitHub Action puts a deterministic regex pre-filter (`findings_filter.py`) in front
  of the LLM filter, and defaults `run-every-commit` to **false** because reviewing every commit
  raises false positives. The Action's README states it "is not hardened against prompt injection
  attacks and should only be used to review trusted PRs".
  <https://github.com/anthropics/claude-code-security-review>
- **[C]** Claude Code best practices: "a fresh context improves code review since Claude won't be
  biased toward code it just wrote", and in the same page: "a reviewer prompted to find gaps will
  usually report some, even when the work is sound… Chasing every finding leads to
  over-engineering." <https://code.claude.com/docs/en/best-practices>
- **[C]** LLM SAST triage, 2026: SAST false-positive rates above 92% on the OWASP Benchmark
  reduced to as low as **6.3%** by LLM agents; best real-world CodeQL configuration reached
  **93.3%** FP identification; SWE-agent with Claude Sonnet 4 identified 95.5% of FPs at 95.5%
  precision against 36.4% for vanilla prompting. Aggressive FP reduction suppressed some true
  vulnerabilities.
- **[C]** Ruff: 10–100× over Flake8, Dagster's 250k-LOC codebase in **0.4 s** where pylint took
  ~2.5 minutes on 4 cores. Gitleaks is feature-frozen (security patches only) but supports
  `--baseline-path` and per-finding fingerprints, which is what makes it usable as an incremental
  gate. Semgrep's MCP server now ships inside the main `semgrep` binary; the standalone repo is
  deprecated.
- **[S]** The built-in `code-review` skill, read out of the local 2.1.270 binary by one lane and
  not independently re-verified: angle decomposition (line-by-line hunk scan *including the
  enclosing function*; removed-behavior audit; cross-file caller tracer; language-pitfall;
  wrapper/proxy; plus reuse/simplification/efficiency/altitude/conventions), per-effort finding
  caps of 4/8/10/15 **by effort level, never by diff size**, a 3-state CONFIRMED / PLAUSIBLE /
  REFUTED vote that is "PLAUSIBLE by default", and the line *"finders that silently drop
  half-believed candidates bypass the verify step and are the dominant cause of misses."*

## 4. Claude Code mechanics that changed the design

All **[C]** unless marked. Sources: `code.claude.com/docs/en/{sub-agents,agent-teams,hooks,
skills,prompt-caching,costs,workflows,advisor,fast-mode,model-config,worktrees,
cross-session-messaging}` and `platform.claude.com/docs/en/build-with-claude/prompt-caching`.

**Subagent frontmatter, complete:** `name`, `description` (only two required), `tools`,
`disallowedTools`, `model`, `permissionMode`, `maxTurns`, `skills`, `mcpServers`, `hooks`,
`memory`, `background`, `omitClaudeMd`, `effort`, `isolation`, `color`, `initialPrompt`,
`experimental` (`cacheTtl`: `5m` | `1h`).

- Model resolution: per-invocation → frontmatter (`inherit` = main model) →
  `CLAUDE_CODE_SUBAGENT_MODEL` → main conversation. Before v2.1.251 the env var came first.
  `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` (2.1.257+) ignores every `model:` field.
- `maxTurns`: on hit, output is returned **marked partial** (2.1.246+) and the agent can be
  **resumed via `SendMessage`** with full history and a warm cache. Explore and Plan are one-shot.
- **Subagents spawn subagents up to three layers by default** — so
  `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` is load-bearing, not documentation. A separate
  `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` defaults to 20.
- **Fork mode is on by default in interactive sessions (2.1.232+), so every spawned subagent runs
  in the background.** Background subagents keep all MCP tools but only a fixed set of built-ins
  (`Read`, `Grep`, `Glob`, `Bash`, `PowerShell`, `Edit`, `Write`, `NotebookEdit`, `WebFetch`,
  `WebSearch`, `TodoWrite`, `Skill`, `ToolSearch`, `EnterWorktree`, `ExitWorktree`, `Monitor`,
  `TaskStop`, `SendMessage`, `Artifact`); a `tools` list that resolves to nothing fails to launch.
- Startup context: own system prompt + environment, the delegation message, **every level of the
  CLAUDE.md hierarchy**, a git-status snapshot from parent session start, preloaded `skills`, and
  a sibling roster. `omitClaudeMd: true` (2.1.271+) drops user/project/local CLAUDE.md. Explore
  and Plan skip CLAUDE.md and git status "to keep research fast and inexpensive".
- **Correct sizing:** the user's global `CLAUDE.md` is 15,304 bytes / 245 lines ≈ 4k tokens —
  over the docs' 200-line guidance, but only **5–10%** of the 38–69k-token prefix a subagent
  request was measured re-reading. **[R]** the claim that it is "the single largest fixed
  per-agent cost".
- `permissionMode` in frontmatter is **ignored** when the main session runs in
  `bypassPermissions`, `acceptEdits` or `auto`. A subagent can never declare its way into
  `bypassPermissions` (2.1.267+).
- **Cache:** subagents, forks, workflows, teammates, compaction and session titles all sit in the
  "everything else" bucket with a **5-minute TTL by default, even on a subscription**;
  `subagentPromptCacheTtl` / `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` (2.1.242+) take `5m`/`1h`;
  `experimental.cacheTtl` per agent (2.1.248+). 1h writes cost 2× base input, 5m writes 1.25×,
  reads ~10% (2.5% on Fable 5.1). Minimum cacheable prompt 512 tokens on Opus 5/Fable 5.1.
  **[R]** "1h is unconditionally the biggest lever" — the docs say it "costs more on short bursts
  of work that never idle past five minutes", and break-even is ~1 turn in 20 pausing 5–60 min.
- **A cache entry does not exist until the first response begins**, so simultaneous sibling
  spawns each pay full price. Workflows stagger same-prefix siblings up to
  `CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS` (default 5000). Sibling sharing requires identical
  model, effort, agent type, tools, output schema and working directory. A subagent's first
  request never reads the parent's cache; a **fork's does** — but a fork also inherits the main
  session's model and sits in the same 5-minute bucket.
- Cache invalidation: switching models, changing effort mid-session (exception: Fable 5.1 on API
  key/subscription keeps it, 2.1.260+), first enabling fast mode, connecting/disconnecting an MCP
  server, enabling/disabling a plugin, denying a whole tool, compaction, upgrading Claude Code.
  Editing files, editing CLAUDE.md, changing permission mode, changing **output style**, and
  invoking skills all keep the cache.
- **MCP overhead: tool definitions are already deferred** — only tool names and server
  instructions enter context until a tool is used. **[R]** "per-agent tool allowlists are the
  biggest token win". The untrimmed part is each server's **instructions prose**; scope it with
  per-agent `mcpServers:`.
- **Worktrees:** branch from the **default branch** unless `worktree.baseRef: "head"`; tracked
  files only, so no `node_modules`, `.venv` or `.env` unless listed in `.worktreeinclude`; and
  **every worktree is a different working directory, which forfeits the whole cached prefix**.
- **Hooks:** `SessionStart`, `Setup`, `InstructionsLoaded`, `UserPromptSubmit`,
  `UserPromptExpansion`, `MessageDisplay`, `PreToolUse`, `PermissionRequest`, `PermissionDenied`,
  `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Notification`, **`SubagentStart`**,
  **`SubagentStop`**, `TaskCreated`, `TaskCompleted`, `Stop`, `StopFailure`, `TeammateIdle`,
  `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `FileChanged`, `WorktreeCreate`,
  `WorktreeRemove`, `PreCompact`, `PostCompact`, `PreModelSwitch`, `PostModelSwitch`,
  `SessionEnd`, `Elicitation`, `ElicitationResult`.
  `SubagentStart` injects `hookSpecificOutput.additionalContext` matched on agent type and cannot
  block; `SubagentStop` gets `agent_transcript_path` + `last_assistant_message` and
  `decision: "block"` keeps the agent running with your reason. `PreToolUse` can rewrite a Bash
  command via `hookSpecificOutput.updatedInput` — docs cite trimming test output "from tens of
  thousands of tokens to hundreds". **A `PreToolUse` command hook that times out does not block
  the call**, so `md-guard.py` is not fail-closed. **[R]** the `async: true` gate hook — async
  hooks cannot gate and the `Edit|Write` matcher fires once per edit.
- **Skills:** listing budgeted at **1% of the context window**
  (`skillListingBudgetFraction`), each entry's description capped at 1,536 chars
  (`skillListingMaxDescChars`); on overflow Claude Code **drops descriptions starting with the
  least-invoked skills**. `/skill-doctor` (2.1.252+) reports each skill's context cost and whether
  it has ever been invoked; `skillOverrides` can set an entry to `"name-only"`. A subagent's
  `skills:` field preloads full skill content at startup. Invoked skill bodies survive compaction
  only up to 5,000 tokens each / 25,000 total.
- **Agent teams:** experimental, off by default behind `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`;
  ~**7× tokens** when teammates run in plan mode; no nested teams; no worktree isolation of
  teammates; split panes need tmux/iTerm2 so Windows gets in-process only; a teammate **ignores a
  subagent definition's `skills` and `mcpServers`**; and **while teams are enabled, any subagent
  Claude *names* launches as a teammate instead.**
- **Workflows:** shipped on all paid plans (2.1.154, keyword renamed to `ultracode` in 2.1.160);
  16 concurrent agents locally (`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` 1–256 since 2.1.269),
  4,096 items per `parallel()`/`pipeline()`, 1,000 agents per run; `schema` forces validated
  structured output with up to `MAX_STRUCTURED_OUTPUT_RETRIES` retries; resume re-runs the first
  changed agent **and everything after it**.
- **Models:** Fable 5.1 $10/$50 (1M ctx, default effort high, adaptive thinking always on);
  Opus 5 $5/$25 (1M); Sonnet 5 $2/$10 (1M, supports `xhigh` and `max`); Haiku 4.5 $1/$5 (200K,
  **does not support `effort` at all**). Guidance: *"start with Claude Opus 5 for most
  workloads. Use Claude Fable 5.1 for demanding reasoning and long-horizon agentic work, or when
  your evals on Claude Opus 5 at higher effort still fall short."* `xhigh` is documented for
  "long-running agentic and coding tasks (over 30 minutes) with token budgets in the millions";
  `low` is the documented typical setting for subagents; higher effort buys quality **by making
  more tool calls**. `maxEffortLevel` (2.1.267+) silently caps every pin.
- **`/advisor`:** a stronger model consulted at decision points, server-side, and **subagents
  inherit it**. Opus 5 accepts a Fable or Opus 5 advisor; Fable 5.1 accepts only Fable 5.1.
  Anthropic measured Opus 5 executor + Fable 5.1 advisor as their **most accurate** configuration
  at $7.69/attempt, +3.5 points over Opus 5 alone at similar cost, ~2–3 consults per task.
  **[R] as a default**: "the advisor model's own read of the conversation is not cached — each
  advisor call processes the full transcript anew, with no reuse between calls"; on subscription
  plans a Fable advisor bills to **usage credits, outside the plan**; the gain shrinks as the
  executor gets stronger and **inverts if you lower executor effort**; and the advisor is off
  entirely when feature-flag fetching is disabled (e.g. `DISABLE_TELEMETRY`).
- **Fast mode:** research preview; up to **2.5×** faster Opus 5/4.8 at a flat $10/$50 across the
  1M window, billed from usage credits; enabling it mid-conversation costs the full uncached
  input once. Docs say to leave long autonomous agent runs at standard speed.
- **Built-in agents:** Explore, Plan, general-purpose, plus `claude`, `statusline-setup`
  (Sonnet) and `claude-code-guide` (Haiku). Since 2.1.198 **Explore inherits the main
  conversation's model**, and a user/project agent named `Explore` overrides the built-in while
  keeping its own `model` — so shadowing it with `model: haiku` is the sanctioned way to keep
  location lookups cheap. `/code-review` (renamed from `/simplify` in 2.1.147) runs as a
  background, effort-tunable review subagent.
- **Measurement:** `CLAUDE_CODE_ENABLE_TELEMETRY` emits `claude_code.subagent_completed`
  (`duration_ms`, `total_tool_uses`, `total_tokens`, `agent_type`, `model`, `is_async`) and
  `claude_code.api_request` (`duration_ms`, `cost_usd`, `input_tokens`, `output_tokens`,
  `cache_read_tokens`, `cache_creation_tokens`, `effort`, `query_source`). Free without setup:
  **`/insights`** (up to 200 recent sessions → `~/.claude/usage-data/report.html`), **`/usage`**
  (`Total duration (API)` vs `(wall)`, attribution by skill/subagent/plugin/MCP server — resets
  on `/clear`, and its cache line covers the main conversation only), **`/context`**, and the
  per-agent transcripts at
  `~/.claude/projects/{project}/{sessionId}/subagents/agent-*.jsonl`.
- Breaking default changes worth knowing: project `.claude/settings.json` `env` can no longer set
  `CLAUDE_CONFIG_DIR`/`TMPDIR` (2.1.251); `autoMode` no longer read from
  `settings.local.json` (2.1.207); repo-local settings can no longer enable Remote Control
  (2.1.222); the `/agents` wizard was removed (2.1.198); the Task tool's `mode` parameter is
  ignored (2.1.212).

## 5. Community frameworks

- **[C]** Same real feature (medium backend addition, security + auth + IaC), four flows:
  **BMAD Full 2 days planning + 4 days implementation, $50 + $150; BMAD Quick 5h + 1.5d,
  $30 + $55; Spec-Kit 4h + 1d, $30 + $45; OpenSpec 3h + 1d, $25 + $70.** The light three were
  "noise" apart from each other. BMAD Full: 2/5 time-to-PR, 2/5 developer experience, 2/5 human
  checkpoints; its 5/5s were iterative refinement and course correction, and its adversarial code
  review "caught things a standard review would miss".
- **[C]** BMAD's own bug tracker: create-story steps at **80k–100k tokens each** against a
  1,400-line PRD and 4,800-line architecture doc; maintainers' root cause *"Workflows perform
  unbounded deep analysis of architecture/PRD documents rather than targeted, context-limited
  reading"*; impact *"Makes workflows impractical for normal-sized projects."* 53.1k stars.
- **[C]** First-hand abandonment: *"they burn 10x more tokens… I was always hitting the Max plan
  limits for no discernable benefit"*; *"Plan Mode had a plan and then base implementation in
  twenty minutes. GSD ran for hours to achieve the same thing"* (with the honest counterpoint that
  the GSD code fit the wider project while plan mode's was MVP-only); *"hit the 5-hour limits in
  ~30 minutes and my weekly limits by Tuesday"*; *"a lot of ceremony and complication for not much
  value."*
- **[C]** The one practitioner who ran their own evals: *"the planning ceremony is mostly
  useless… what makes a difference is running plan review and work review agent… the most
  surprising is the plan-review one… they should run from separate subagents not main one because
  they need a fresh perspective."* We took the work-review half and **[R]** rejected the
  plan-review half — one anonymous unpublished eval is not enough to add a serial step.
- **[C]** Direction of travel: **Agent OS v3** is now "a lightweight system for defining and
  managing your coding standards" that "complements" Claude Code; **spec-kit** now states its
  three processes "are independent entry points, not three mandatory phases" and was scored 2/5
  on project health with no built-in code review step. **claude-flow → ruflo** advertises "98
  agents, 60+ commands, 30 skills, MCP server, hooks, daemon". **SuperClaude**'s "2-3x faster,
  30-50% fewer tokens" is unbenchmarked README marketing. **obra/superpowers** contributes two
  transferable mechanics: plan tasks sized to 2–5 minutes with named verification, and a
  two-stage review split into spec-compliance then code-quality.
- **[C]** Task Master prices MCP overhead in its own README: 36 tools ≈ 21,000 tokens, 7 tools
  ≈ 5,000 — the figure that produced the refuted "tool allowlists are the biggest win" claim.
